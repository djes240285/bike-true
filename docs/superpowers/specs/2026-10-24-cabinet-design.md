# BikeTrue — кабинет

Дата: 24 октября 2026. Статус: спецификация, к реализации после ревью.

Человек может войти и хранить несколько посадок: мерки тела, велосипеды и снимки углов. Разбор фото по-прежнему считается в браузере. Кабинет запоминает результат, если человек сам нажал «сохранить».

Подбор велосипеда до покупки, разные коридоры углов для разных посадок, цветные метки на теле, магазины, подписка и донат в эту спецификацию не входят. Кабинет уже хранит посадку и размеры, чтобы эти шаги читали одни и те же поля.

## Как это стыкуется с сайтом

Сайт остаётся Astro на Netlify. Новый процесс — HTTP-сервер на Bun, каталог `api/` в этом репозитории. База — MySQL 8. Страницы кабинета — React-островки на тех же маршрутах, что и остальной сайт. Русский без префикса, английский под `/en`.

```
Браузер
  фото → MediaPipe → углы на экране
  «Сохранить» → JSON без файла → API
API (Hono)
  вход, мерки, велосипеды, снимки углов → MySQL 8
```

Заявка «позвать на посадку» остаётся функцией Netlify и сообщением в Telegram. В кабинет она не пишется.

Пока сайт закрыт паролем, API поднимается только локально и на прод не выкладывается. На проде сайт и API открываются вместе.

Локальный клиент MySQL 5.7 к этому приложению не подключается. Нужен сервер MySQL 8 и база `biketrue`.

| `role` | `rider` или `fitter`. Новый человек — `rider` |

| `token_hash` | sha256 от случайных 32 байт, уникально |
| `expires_at` | сейчас + 30 дней |
| `created_at` | |

`oauth_states`

| Поле | Правило |
| --- | --- |
| `state` | случайная строка, первичный ключ |
| `provider` | `google` или `yandex` |
| `user_id` | `null`, либо человек, который уже вошёл и привязывает второй вход |
| `expires_at` | сейчас + 10 минут |

Строка одноразовая: проверка удаляет её сразу.

`profiles`

Одна строка на человека. Пока человек не сохранил мерки, строки нет.

| Поле | Правило |
| --- | --- |
| `user_id` | первичный ключ и внешний ключ, удаление пользователя удаляет мерки |
| `rider` | `child`, `teen`, `adult` или `null` |
| `height_cm` | целое 90–220 или `null` |
| `inseam_cm` | шов книгой, целое 40–110 или `null` |
| `updated_at` | |

Если заполнены и рост, и шов, шов меньше роста.

`inseam_cm` — это не портновский шов штанов. Это расстояние от книги до пола, как на видео у байкфитеров. Человек встаёт спиной к стене в обуви, в которой будет кататься. Книга между ног, плотно к промежности, корешок горизонтально. Меряют от верхней грани книги, той, что упёрлась в тело, до пола. Подошва уже внутри числа. Отдельного поля «высота обуви» нет: второй раз прибавлять её нельзя. Босиком и в другой обуви этот замер не сохраняют.

Запрос `PUT /profile` всегда присылает три поля: `rider`, `height_cm`, `inseam_cm`. Пустое поле записывается как `null` и стирает прежнее значение.

`bikes`

| Поле | Правило |
| --- | --- |
| `id` | ключ |
| `user_id` | внешний ключ, удаление пользователя удаляет велосипеды |
| `name` | 1–40 символов |
| `fit` | одна из четырёх посадок |
| `crank_mm` | целое 120–180 или `null` |
| `saddle_mm` | высота седла от каретки, целое 400–1000 или `null` |
| `stem_mm` | целое 30–150 или `null` |
| `drop_mm` | падение руля относительно седла, целое от −150 до 200 или `null`. Отрицательное — руль выше седла |
| `created_at` | |
| `updated_at` | |

Не больше 20 велосипедов на человека.

`readings`

| Поле | Правило |
| --- | --- |
| `id` | ключ |
| `user_id` | внешний ключ, удаление пользователя удаляет снимки |
| `bike_id` | внешний ключ или `null`. Удаление велосипеда ставит `null`, снимок остаётся |
| `fit` | посадка на момент сохранения |
| `knee` `back` `arm` `hip` | целое число градусов или `null` |
| `had_top` | был ли кадр с шатуном вверху |
| `created_at` | |

Хотя бы один из четырёх углов не `null`. Не больше 100 снимков на человека. В строке нет файла, адреса картинки и полей `photo`, `image`, `file`, `dataUrl`.

Размеры велосипеда в этой спецификации только хранятся. На уже посчитанные углы они не влияют. Экран так и говорит: размеры сохранены, расчёт по ним будет отдельным шагом.

## Вход

Три способа: Google, Яндекс, Telegram. Пароля у кабинета нет.

Кука `bt_session` стоит на хосте API. Значение — случайные 32 байта в base64url. В базе лежит sha256. Флаги: `HttpOnly`, `Secure`, `SameSite=None`, `Path=/`, срок 30 дней. `SameSite=None` нужен, потому что сайт и API на разных хостах. Локальный `http://localhost` браузер считает безопасным происхождением, поэтому кука с `Secure` ставится и в разработке.

Браузер ходит на API с `credentials: 'include'` и заголовком `X-BikeTrue: 1`. Любой изменяющий запрос без этого заголовка получает 403. CORS разрешает только `WEB_ORIGIN` и учётные данные. Остальные источники браузер отсекает на preflight.

Связывание входов:

1. Такой вход уже есть — открыть сессию этого человека.
2. Человек уже в сессии, и этот вход ещё ничей — привязать к нему.
3. Человек уже в сессии, а вход принадлежит другому — ответ 409, учётки не сливать.
4. Сессии нет, входа нет, у Google или Яндекса почта совпала с уже существующей — привязать и войти.
5. Сессии нет и совпадения нет — создать человека. Имя взять у провайдера.
6. Telegram без почты и без входа создаёт нового человека. С почтой Google или Яндекса он сам не сливается, пока человек, уже войдя, не нажмёт второй способ входа.

Выход удаляет текущую сессию и куку. Удаление кабинета удаляет человека и все его строки.

Провайдеры:

- Google, код авторизации, области `openid email profile`. Адрес возврата `{API_ORIGIN}/auth/google/callback`.
- Яндекс, код авторизации, права `login:email` и `login:info`. Адрес возврата `{API_ORIGIN}/auth/yandex/callback`.
- Telegram Login Widget. Браузер отдаёт на `POST /auth/telegram` поля виджета. Сервер проверяет `hash` ключом sha256 от токена бота и отвергает `auth_date` старше суток. Токен тот же, что у заявки в Telegram, если это один бот.

Роль `fitter` в интерфейсе не выдаётся. Её ставят вручную после первого входа: `UPDATE users SET role = 'fitter' WHERE id = …`.

## HTTP

Ответы JSON. Ошибка: `{ "ok": false, "error": "<код>" }`. Успех мутаций: `{ "ok": true }`.

| Метод и путь | Кто | Что делает |
| --- | --- | --- |
| `GET /auth/google` | гость или сессия | редирект на Google, в `oauth_states` пишется `state` |
| `GET /auth/google/callback` | Google | проверка `state`, связывание, кука, редирект на `{WEB_ORIGIN}/account` |
| `GET /auth/yandex` | гость или сессия | то же для Яндекса |
| `GET /auth/yandex/callback` | Яндекс | то же |
| `POST /auth/telegram` | гость или сессия | проверка виджета, связывание, кука |
| `POST /auth/logout` | сессия | удалить сессию |
| `DELETE /me` | сессия | удалить кабинет |
| `GET /me` | сессия | имя, почта, роль, список провайдеров, мерки или `null` |
| `PUT /me` | сессия | сменить имя |
| `PUT /profile` | сессия | записать `rider`, рост и шов книгой. Все три поля обязательны в теле, пустое стирает прежнее в `null` |
| `GET /bikes` | сессия | велосипеды этого человека, новые сверху |
| `POST /bikes` | сессия | создать |
| `PUT /bikes/:id` | владелец | заменить поля |
| `DELETE /bikes/:id` | владелец | удалить, у снимков `bike_id` становится `null` |
| `GET /readings` | сессия | последние 50 снимков |
| `POST /readings` | сессия | сохранить углы, посадку и необязательный `bike_id` |
| `DELETE /readings/:id` | владелец | удалить снимок |
| `GET /studio` | `fitter` | последние 100 снимков всех людей: дата, имя, посадка, имя велосипеда, четыре угла |

Чужой `bike_id` и чужой снимок — 404. Роль `rider` на `/studio` — 403. Нет сессии — 401.

Коды ошибок: `session`, `forbidden`, `state`, `provider`, `telegram`, `taken`, `name`, `rider`, `height`, `inseam`, `fit`, `bike`, `limit`, `angles`, `photo`. `taken` — попытка слить две уже существующие учётки. `photo` — в теле есть поле картинки. `limit` — потолок велосипедов или снимков.

## Экраны

Строки лежат в `src/i18n.ts`, как у остальных страниц.

| Путь | Содержание |
| --- | --- |
| `/account` | Без сессии: три кнопки входа. С сессией: имя, почта, подключённые входы, кнопки «подключить» для недостающих, выход, удаление кабинета |
| `/account/body` | Кто едет, рост и шов книгой. Над полем шва короткая инструкция: стена, книга между ног, обувь для катания, мерка от верхней грани книги до пола. Кнопка сохранения |
| `/account/bikes` | Список. Форма: имя, посадка, шатун, высота седла, вынос, падение руля. Пустые размеры допустимы. Под формой фраза, что на углы с фото эти числа пока не влияют |
| `/account/readings` | Последние 50 снимков: дата, посадка, велосипед или «без велосипеда», четыре угла, удаление |
| `/studio` | Только для `fitter`. Тот же снимок плюс имя человека. Остальным — короткий отказ и ссылка в свой кабинет |
| `/analyze` | После готового разбора кнопка «Сохранить в кабинет». Без сессии она ведёт на `/account` и после входа возвращает на разбор. Рядом выбор: один из своих велосипедов или «без велосипеда». Если велосипеды есть, по умолчанию выбран последний сохранённый. С велосипедом в снимок пишется его посадка и `bike_id`. Без велосипеда посадка `endurance`, `bike_id` пустой. В снимок пишутся целые градусы с экрана и `had_top` |

Навигация сайта получает пункт «Кабинет».

Главная сейчас обещает «Без регистрации». Разбор без входа остаётся. Эта строка меняется на «Можно без входа» / «No account needed». В вопросах и в приватности остаётся правда про фото: снимок не уходит на сервер. Рядом добавляется: если нажать «сохранить», на сервер уходят имя, почта провайдера, мерки, размеры велосипеда и градусы углов. Кука сессии стоит на хосте API, не на сайте.

Локальные углы и кадры в браузере не удаляются в момент сохранения. Устройство по-прежнему помнит последний разбор само.

## Окружение

В процессе API:

- `DATABASE_URL`
- `WEB_ORIGIN`
- `API_ORIGIN`
- `GOOGLE_CLIENT_ID`
- `GOOGLE_CLIENT_SECRET`
- `YANDEX_CLIENT_ID`
- `YANDEX_CLIENT_SECRET`
- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_BOT_USERNAME`

В сборке сайта одна публичная переменная `PUBLIC_API_URL`. Пока она пустая, кнопки кабинета показывают, что сохранение временно недоступно, а разбор фото работает как раньше.

Секреты в репозиторий не попадают. Рядом с `.env.example` появляются только имена переменных.

## Разработка

- Сайт: `bun dev`, порт Astro.
- API: `bun run api`, порт 8787.
- Миграции: `bun run api:migrate`.
- `WEB_ORIGIN` локально `http://localhost:4321`, `PUBLIC_API_URL` локально `http://localhost:8787`.

Проверка правил без живой базы, командой `bun test src/lib`, как у остальных чистых функций:

- рост, шов книгой и «шов меньше роста» принимают край и отвергают шаг за краем;
- размеры велосипеда так же;
- неизвестная посадка и неизвестный `rider` отвергаются;
- снимок без единого угла отвергается;
- тело с полем картинки отвергается тем же списком ключей, что заявка на визит;
- проверка подписи Telegram: верный `hash` проходит, порченый и просроченный `auth_date` нет;
- хеш сессии не равен самой куке.

Запрос к живому MySQL в автоматический прогон не входит.

## Что сознательно не делаем

Разные коридоры для четырёх посадок. Страницу подбора до покупки: когда она появится, шов берётся из этого же поля, второе измерение не заводится. Формулу высоты седла из шва. Отдельную мерку босиком и отдельную высоту подошвы. Метки изолентой и перевод пикселей в сантиметры. Видео. Хранение фото. Оплату, донат и ограничение кабинета подпиской. Слияние двух уже созданных людей. Письмо-пароль. Перенос заявки визита из Telegram в MySQL. Админку отдельным приложением: мастеру хватает `/studio`.
